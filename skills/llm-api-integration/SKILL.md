# LLM API 接入与复用

适用于给程序增加摘要、分类、推荐、解释或笔记生成等 LLM 功能，以及实际 API 接入、配置与排错。普通对话中的摘要和知识问答不因此变成应用开发；新功能是否需要 LLM，先根据业务收益判断。

## 先复用已有信息

- 使用者已有系统凭据时优先复用。Windows 可使用凭据管理器。先查当前项目的非敏感配置、凭据定位函数和[凭据复用示例](references/credentials-and-profiles.md)，不要默认要求重新贴 key、写 `.env` 或新建凭据。条目定位、条目存在、可读取、密钥有效是不同结论；本机 Windows 凭据不自动出现在 SSH 远端、WSL 或其他登录用户中。
- 新增 OpenAI 官方接入时，以 Responses 和可用的 Flex 为个人优先方案；已有程序或用户指定的协议、供应商、模型和获批策略优先。Flex 不可用或延迟不合适时说明取舍，不静默切换更贵等级。兼容网关不自动继承官方能力。
- 先确定本次有效的 provider、base URL/完整 endpoint、协议、精确 model ID、凭据引用、服务等级、输入/输出预算及超时。已有信息自行查证；仅对无法确定且会改变行为或费用的缺口询问。配置中的密钥只在请求进程内取用，不进入对话、日志、Skill、命令行或版本库。

## 从业务需求到可用功能

1. 确定模型需要完成的语义任务及结果用途。取材、筛选、去重、数值统计、权限和写回由程序负责；保留来源标识。简单文本任务直接返回文本，下游需要稳定字段时再用结构化输出；只有确需外部动作时引入工具调用。
2. 复用已有配置与凭据引用，形成有效参数和费用／重试策略。已有项目选择优先；缺失时再用已确认的个人偏好，不能拿旧客户端快照冒充当前设置。需要时核对供应商能力，不因请求格式兼容就推定 Flex、工具、存储或恢复可用。
3. 在现有职责处实现最小接入：准备材料 → 请求模型 → 终态与业务校验 → 预览／保存／应用。复用现有异步与错误通道，长调用不阻塞界面；流式内容只作预览，未验证结果不覆盖旧有效结果。
4. 失败先确定所处阶段。已收到的响应和已知用量按任务需要保留；结果有效而本地导出失败时优先重做本地阶段，不重新生成。收费结果未知时按已有策略恢复或停止，不盲目重发或更换模型／档位。
5. 用本次所需的离线样例检查最终请求和结果处理，再按明确授权做必要真实验证。交付说明有效配置来源、实际验证、费用策略及缺口，不把保存配置、模拟成功或 HTTP 200 当作完整业务通过。

这些是接入过程中的判断，不要求每项另写报告。任务级调用策略已获批准时按其预算和停止条件执行，不为每次请求重复索要许可。

## 实施和验收

- 沿用现有配置、凭据、HTTP/SDK 与测试结构；新程序只划分必要的配置/凭据读取、协议请求/结果解析和调用方职责，不强制搭建通用网关、插件框架或调用账本。
- 严格区分模型能力上限、客户端配置上限和本次任务预算。不要把示例的 4096、10240 或 128000 无条件复制到所有请求；也不要未经说明把用户要求的输出能力改成较小的 SDK 默认值。
- HTTP 200、有文本、收到 response ID 都不等于成功。核对协议终态与业务所需结果；保存已知 usage 和失败原因。收费请求结果未知、流中断或 incomplete 时，不自动重发、提高预算或换模型；恢复/重试遵循本次授权及已有明确策略。
- 涉及请求构造或恢复逻辑时，优先用真实 SDK 配合模拟 HTTP 验证最终 URL、字段、终态和请求次数；普通配置变更不新增无关测试。示例采用离线传输，不读取实际凭据或调用网络，也不证明供应商账号可用。
- 用离线响应样例验证本次涉及的协议和失败分支；客户端配置读回只能证明保存。真实调用只在授权范围内做一次足够小的验证，不为创建本技能或“保存设置”发收费请求。报告结构检查、模拟验证、真实调用各自范围，不把已存 key 或 `/models` 成功当成生成成功。

维护原则：个人偏好保留在此入口；凭据标识、客户端路径与易变规格保留在资料中，并注明日期和证据。新项目经验仍保存在该项目；只有跨项目确实可复用的结论才更新本技能。
