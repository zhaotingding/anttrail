# 业务流程与最小接入示例

读取时机：为程序增加摘要、分类、推荐、解释、规则或笔记生成；确定同步／后台交互、结果写回或最小实现方式。仅在聊天中要求一段摘要，不触发本流程。

## 先分清程序和模型的职责

最小流程：用户操作／已批准任务 → 程序取材与预处理 → 按有效档案调用模型 → 协议终态与业务校验 → 预览、保存或应用。

| 场景 | 程序负责 | 模型负责 | 写回前的业务判断 |
| --- | --- | --- | --- |
| 消息摘要 | 时间范围、筛选去重、统计、来源 ID | 摘要与语义分类 | 引用属于输入，覆盖所需范围，不编造统计 |
| 计算任务监控 | 采集状态、规则匹配和调度 | 解释日志、提出受约束规则 | 规则字段及语义合法；无效新规则不覆盖旧结果 |
| 文献笔记 | 获取选区／批注、文献与页码，写入笔记 | 归纳、比较与解释 | 引用能定位，写回位置正确；材料不足时不造出处 |
| 仓库推荐 | 取候选、去重、读取 README、计算统计、保存证据 | 语义匹配、理由与教程 | 选择来自候选集，理由有依据，动态统计不是模型猜测 |

表中示例说明职责分工。预算、存储与写回规则按各应用自身的契约确定。

- 先定义一个可观察的结果，例如“选中的三条消息生成带来源 ID 的摘要”；不以“更智能”替代任务契约。先打通一条真实业务路径，再扩展功能。
- 可由既有代码可靠完成的过滤、数值运算、权限和落盘继续由程序处理。模型负责确有收益的语义任务，不让它直接决定任意 Shell、文件写入或发送动作。
- 自由文本结果可直接检查内容；需要稳定字段时用项目已有类型定义生成 Schema 并本地验证。只在任务需要调用工具时设计工具回合，不把每次摘要包装成 Agent。
- 来源材料与指令分开组织，保留必要出处和上下文。不要为省 token 静默丢弃决定结论的材料；过长时按任务设计分块／检索并注明覆盖范围。

## 让默认偏好进入实际请求

项目已选配置／用户明确要求 → 已确认个人偏好 → 必要缺口才询问。OpenAI 官方新接入优先 Responses，模型支持且延迟允许时优先 Flex；其他供应商使用自己的能力表。

取材前先识别当前档案的 provider、endpoint、协议、模型、credential_ref、预算及重试／档位策略。凭据按[凭据复用示例](credentials-and-profiles.md)复用；若程序已有凭据读取函数，在获准调用的进程内调用它，不为了一个示例新增共享密钥服务。新用户分发走其自身凭据配置流程，不能嵌入维护者 target 或个人目录。

任务级策略确认后按其执行，不能每次请求再问相同配置，也不能把“曾允许某项目转 Standard”扩展成所有应用的升价许可。

## 界面与后台流程

- 复用应用已有异步任务机制；UI 可以显示等待、生成预览、完成、失败及取消等实际状态。Flex 慢响应时告知正在等待，不伪造百分比或把无输出立即判成失败。
- 流式内容可显示但不能提前覆盖已保存的有效规则或笔记；只有合法终态和业务检查通过后才应用结果。
- 取消信号传给持有请求的后端；传输关闭与供应商确认取消分开。请求状态未知时如实显示，不能自动重新生成。
- 结果已有效而导出失败时保留结果，只重试本地步骤。是否持久保存根据任务时长、费用及已有存储决定；不为短交互自动增加数据库。
- 主进程／后端承担凭据与受控系统操作，前端只拿必要的状态和结果。多个 UI 入口复用同一业务职责，不并行创造多套计费或重试逻辑。

## 两个可运行的离线示例

这些文件是可选学习素材，不是要导入每个项目的通用库。它们固定使用非真实域名、模拟传输与虚构材料，不接受实际 endpoint 或 key，不读取环境密钥、Windows 凭据或应用配置。不要仅替换 URL 就将其视为生产接入。

1. [Responses 与业务验证示例](../assets/examples/responses_offline.py)：使用真实 OpenAI Python SDK 和 httpx.MockTransport，分别模拟 OpenAI／DeepSeek 请求。展示预算与 Schema 构造、仅官方请求 Flex、完成／拒绝／截断／Schema／来源校验，以及先保留已知用量再处理错误；另用真实 SDK 解析模拟 SSE，检查完成、失败、截断与缺失终态。内置检查确认一次失败没有隐式重发。
2. [桌面任务流程示例](../assets/examples/desktop_task.mjs)：纯 JavaScript，无框架或网络依赖。展示异步预览、验证后应用、取消与本地写回失败；导出失败保留有效结果，可只重试写回。

在已具备依赖的项目环境运行，不为阅读示例自动安装依赖。Python 需要 openai、httpx、pydantic；JavaScript 使用 Node 内置功能。进入本 Skill 目录后运行以下命令。示例环境名为 `anttrail-demo`，请换成已有环境名。

```powershell
conda run -n anttrail-demo python -I -X utf8 assets/examples/responses_offline.py
node assets/examples/desktop_task.mjs
```

2026-11-13 离线验证使用 OpenAI Python 2.54.0、httpx 0.28.1、Pydantic 2.14.2 与 Node 20.19.0；版本是验证记录，不是所有项目强制依赖。示例只有本地模拟能力，不验证真实供应商接受 Schema、账号权限、计费或远端取消。按本次改动选择相关检查，不要求每个任务重跑整套示例。

## 借鉴来源与适用限度

- [OpenAI Python SDK](https://github.com/openai/openai-python)及[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)：借鉴正式 SDK、类型和终态处理；模型号、预算、默认重试和凭据方式不能直接套用。
- [Vercel AI SDK 结构化流](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data)与[界面状态](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot)：借鉴部分输出与最终结果的区分；不为 Python 程序引入整套前端框架。
- [zotero-gpt 应用接口](https://github.com/MuiseDestiny/zotero-gpt/blob/ethereal/src/modules/Meet/api.ts)：借鉴“取选区／批注 → 语义处理 → 笔记写回”的职责。公开分支与发布版可能不同，不照搬旧请求实现或将其当本机插件实测。

资料核对日期 2026-11-13；本地参考已概括需要采用的做法，不要求每次联网阅读这些完整项目。更多分场景用法见[项目与客户端适配](client-and-project-adapters.md)。
