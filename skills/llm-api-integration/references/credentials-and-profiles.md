# 凭据与有效配置

先确定请求进程以哪个用户、在哪台机器上运行。下面的 `example-summary` 和 `https://provider.example.invalid/v1` 是虚构标识，仅用于说明。每位使用者管理自己的凭据。

## 复用已有凭据

Windows 应用优先复用本应用或用户明确选定的凭据管理器条目。先查项目的非敏感配置与已有读取函数，例如按 `(profile_id, endpoint)` 定位凭据。如果应用约定采用其他身份组成方式，保留其兼容契约。凭据标识、读权限和服务商验证结果分别记录。SSH、WSL、服务账号与桌面进程可能处于不同用户或机器。

档案可保存供应商、有效地址、协议、模型、档位、预算和一个凭据引用。实际密钥只在授权的请求进程内取用。显示来源和字段是否配置，避免把值写入日志、Markdown、命令行、导出文件或渲染进程。

## 新应用与恢复

- 提供“从已有档案选择”和“创建自己的档案”。收到新地址或协议时校验凭据适用范围；同一家供应商的不同网关也可能属于不同账号。
- 设置页区分草稿、已保存的偏好和在途任务的快照。局部保存时先读回最新配置，再更新该字段。留空的秘密字段保留原值，删除或轮换凭据需明确操作。
- 离线验收用虚构标识或 SDK 模拟传输，覆盖缺少配置、无法读取、已取到结果而本地保存失败等所需分支。真实调用及可能产生的费用遵守使用者批准的预算。
- 公共配置、安装器与备份模板只携带字段结构。新安装由使用者自行选用凭据及服务档位。
