# Flex、模型容量与请求预算

读取时机：配置服务等级、最大输入输出、推理强度、超时、费用或诊断截断。按使用时的模型与供应商文档核对容量和费率。

## 用户默认与实际能力

- 本人的新 OpenAI 官方接入优先 Responses + Flex；来源是用户重复提出的需求与现有应用设置。已有项目获批策略、交互延迟要求和用户本次指定优先。不要把 Flex 作为所有供应商的通用参数，或写入模型 ID 后缀就认为已启用。
- 显式发送 `service_tier="flex"`；记录请求值及返回的实际 `service_tier`。返回缺失只能说明本次请求了 Flex，不能证明实际以 Flex 服务/计费。价格取供应商与精确模型的当前价，保留计价日期；不按显示名含“Flex”来计算。
- 官方 Flex 用较慢响应和偶发资源不可用换较低成本；明确的 `429 Resource Unavailable` 与提交后断线不同。仅按既有授权策略退避重试；若需要改为 Standard/auto，先确认费用策略，不默认静默升级。不同应用可以采用不同的已授权回退策略。
- 读超时需同时考虑有效服务档位、业务时限和客户端能力。一次慢响应只说明此次尚未收到预期结果。

## 四个不要混淆的量

1. **模型上下文窗口**：整次请求可容纳的输入及生成相关 token，包含系统/开发者提示、历史、工具/Schema、必要的多模态输入等开销。
2. **模型最大输出**：模型允许的生成上限；不表示每次请求都应该设到上限。
3. **应用配置上限**：UI/SDK/网关可能另有限制，需顺着真实请求构造路径核对，不能只看设置界面。
4. **单次任务预算**：实际发出的输出限制和输入裁剪/拒绝策略。字符数不是 token 数，也不能用固定中英换算比保证装得下。

按实际模型和供应商计数/估算输入，给预期输出、推理与工具回合留余量；预算应受模型、网关及应用三者约束。业务需要完整输入时，超限明确提示或按任务设计分块，不能默默截断。

Responses 的 `max_output_tokens` 包含可见输出和推理等生成开销；高推理预算会挤占可见答案。`incomplete` 不代表未收费；未看到正文也可能已产生推理用量。修复预算问题应先说明哪一层限制生效，再改实际请求参数，不直接把所有预算改成最大值。

## 核对当前模型

记录精确模型 ID、协议、日期和实际生效配置。结合[供应商能力说明](provider-capabilities.md)以及供应商的当期模型文档、价格表，区分应用自己设置的长度、SDK 上限和模型上限。输入字符数与 token 数分开记录。用量缺失则保留未知，缓存读写和推理用量按供应商计价说明核算。

## 任务级成本策略

2026-11-13 补充。依据任务所需延迟、可接受失败与预算选用，不因为有人在看界面就自动升价。

| 任务条件 | 选择依据 |
| --- | --- |
| 官方模型支持 Flex，用户接受慢响应 | 保留个人优先方案；UI 明确等待状态，期限应与任务相称 |
| 大量相互独立、可异步完成的任务 | 评估供应商 Batch 能力、完成窗口与结果回收方式；Batch 是另一种提交工作流，不只是换 tier 字段 |
| 必须满足较低交互延迟 | 使用已批准的标准或低延迟方案；核实支持情况与当前价格，不因 Flex 暂时拒绝自行升级 |
| 当前项目已有明确策略 | 保持策略；需要改变费用、提供商或回退方式时按当前授权处理 |

- 不写死跨模型的“Flex 半价／Fast 两倍”等倍率，也不把档位名称当作跨供应商标准。需要估价时核对供应商、精确模型、时间、币种、缓存与上下文计价条件；估算与账单分开。
- 单次输出上限、输入处理、任务总调用量／费用预算、工具回合和重试共同约束实际成本。调用次数上限不是金额上限；实际费用未知时标未知，不当作零或已精确封顶。
- 最小记录沿用项目现有日志或存储：业务／请求标识、请求与返回的模型／tier、状态、时间、已知 usage、脱敏错误及费用依据。不存在的字段留未知；不为一个简单功能另造 tracing 平台，不记录 Authorization 或默认保存完整私人材料。
- 请求档位与响应实际档位一致，只能支持服务等级判断；usage 与价格估算不能冒充已核对供应商账单。

## 缓存与并发按需要采用

- 提示缓存复用服务端可缓存的输入前缀，可能节省重复输入成本；业务结果缓存直接复用旧答案。两者不同，使用提示缓存不能证明答案被复用，也不保证本次命中。
- 同一有效结果的本地恢复按材料、提示／规则版本、模型与任务参数判断是否仍适用。语义相似不保证答案等价，不默认添加基于向量相似度的答案缓存。
- 只有确有并行请求时才限制在途数量和队列长度；复用现有调度，必要时用简单信号量。并发值由项目吞吐、账号配额、平均请求大小和预算决定，不给所有程序套一个固定起始值。
- 单人项目不因多应用共用账户就必须建网关。只有确有统一权限、配额或路由需求且收益明确时再评估；网关也不自动获得远端幂等和恢复能力。
