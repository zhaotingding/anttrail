# 业务适配举例

这里只给可移植的流程。实际项目的端点、账号、账本与源码位置以该项目自己的约定为准。

| 场景 | 应由程序掌握的状态 | 失败后从哪里继续 |
| --- | --- | --- |
| 周期摘要 | 周期边界、冻结材料、提示版本、已存响应 ID 与用量 | 有效响应优先本地解析和导出。提交结果未知时保留未知，只有供应商支持且存在原 ID 才取回原请求 |
| 从训练日志生成规则 | 运行身份、脱敏日志、受限规则结构、上一份有效规则 | 新规则验证通过后再替换。解析失败保留原规则，区分人工重试与预算内自动处理 |
| 文献笔记 | 文献 ID、页码、选区、目标笔记和写入权限 | 根据材料检查出处，预览后在获准位置写入。写回失败保留内容，按原对象恢复 |
| 仓库推荐和教程 | 固定候选集、取材版本、明确的生成用途、已验证结果 | 打开已有教程或重新导出 HTML 时复用已生成内容，邮件或其他外发单独判定提交状态 |

客户端界面显示的模型、服务等级、上下文窗口和完整调用是不同证据。排查时对照实际发出的脱敏请求与终态。配置读回可以证明保存成功，接口模拟可以证明本地处理，真实账号能力需有相应授权和真实响应。参考[协议与完成语义](protocols-and-completion.md)与[费用策略](flex-and-limits.md)。
