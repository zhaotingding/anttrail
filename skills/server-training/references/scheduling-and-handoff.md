# 监控、调度能力与批次交接

读取时机：用户要求跟踪任务完成、安排未来检查、接续获批批次或处理锁占用。Skill 文本自身不会生成后台进程、离线执行能力或执行授权。

## 选择当前客户端实际允许的方式

- 跟踪具体训练任务至完成时，优先在当前任务中持续检查，使用真实事件或合适的只读查询等待进展。当前平台若明确禁止用自动化跟踪单个 job，不以 Automations、固定周期提醒或新后台脚本绕过。
- 只有用户明确要求未来调度，且当前客户端提供并允许适用机制时，才使用其正式接口；不能把另一客户端的能力写成通用前提，也不能以保存提示词文件代替任务登记。
- 等待与检查频率依据实际阶段、进度和预计剩余时间；使用当前客户端允许的等待方式。除用户要求周期报告外，仅在完成、失败、重要变化或需要行动时更新，避免重复无变化状态。
- 平台没有所需能力时说明限制和可执行选项；不承诺本机离线后仍能触发检查。服务器训练是否继续、检查是否触发、通知能否送达是不同事实。

## 合法调度场景的登记与核对

明确任务、完整日期、时间、时区及目标对话；复用或更新已有对应登记，避免重复。接口操作后读回实际状态和触发条件；登记成功不等于已经执行，到时仍需核对真实 run。

任何事件、定时唤醒或交接都不自动授权重启、追加实验、改变协议、清理产物或增加费用。只有任务本身已有明确授权时才执行相应动作。

## 运行证据与批次交接

- 记录当前实验与假设、代码版本、生效配置、主机／任务标识、日志及 checkpoint 位置、近期进度、已知故障、剩余预算和下一项获批动作。
- 重新接手时核对当前进程与日志，不能用旧交接记录或缓存代替当前状态。
- SSH 超时、断连或启动响应不明时标“状态未知”；按 run ID 核对启动时间、命令、配置和日志，确认未启动后才在原授权内决定重试，不重复启动可能已经在跑的任务。
- 有依赖的后续实验须满足前置验收条件；无依赖的已获批任务可以在资源和预算内继续。候选方案列表或排队标记不构成启动授权。
- 失败、中止和预算停止保留必要诊断信息与研究判断，说明下一批是否仍有有效依据。

## 写入锁与占用会话

先核实锁及其归属，锁记录与真实进程分别确认。只有现有授权明确允许中断或关闭相关会话，才在保存必要交接信息后使用支持的方式处理。

归属不明、没有安全中断方式或工具权限不足时，暂停受影响操作，继续独立且已获批的工作。不强删锁、不改数据库、不终止无关训练；锁消失也不能单独证明交接成功。

## 相对原调度参考的变更

| 处理 | 原有条款 | 当前规则 |
| --- | --- | --- |
| 保留 | 日志、进程和结果证据；预约成功不等于已触发或完成 | 每次接手、唤醒或检查均核对真实 run，不用缓存或会话名称代替证据 |
| 条件化 | 默认使用应用接口预约下一次单次检查 | 先遵循当前客户端规则；具体 job 在当前任务中跟踪，未来调度仅在用户要求且平台允许时使用 |
| 不沿用通用默认 | 没有事件通知时，转为估计下一次单次检查 | 无事件不代表一定存在合法定时接口；使用当前允许的等待／只读检查方式，能力不足如实说明 |
| 保留 | 完整日期、时区、登记去重、读回实际状态及本机离线限制 | 在确实适用的调度场景执行，不假称提示词文件或后台脚本就是平台任务 |
| 保留并明确 | 唤醒不扩大授权，批次接续须核实当前状态与条件 | 新增、重启、改协议、增费用均依原授权；有依赖批次满足前置条件，无依赖且已获批任务可继续 |
| 保留 | 核实锁归属，保存交接信息，不强删锁或终止无关训练 | 无明确归属和安全中断授权时暂停受影响操作，不新增终止或清理权限 |

实际使用仍服从当前平台规则；本次修订不授予后台运行、无限重试或额外训练权限。
