# 训练服务器接入与工作区定位

## 职责与入口

- 本技能负责接入、定位和连接故障分流，不把连接成功当作训练启动或实验有效。研究、训练、恢复与运行诊断按 `server-training`；实际代码修改按 `code-development`。
- Windows 本地管理远端训练是本技能的示例场景。先确定项目知识与运行产物各自的权威位置。核对实际会话 host/cwd，不凭窗口标题推断后端；与该工作方式不符时先说明差异，按用户和项目约定处理。
- 项目专有映射与跨项目主机事实分开保存。连接、核查、修改配置、写主机表和启动训练是不同操作，均按当前授权范围执行。

| 场景 | 读取 |
| --- | --- |
| 选择主机、定位私有主机表或准备获批更新 | [主机表模板](references/hosts.md)，由使用者指定私有台账，按别名只读对应行 |
| 新连接、连接异常、工作区／磁盘／解释器定位、核对认证方式 | [连接与路径](references/connection-and-paths.md) |
| 用户需要 VS Code 远端编辑，或终端正常但编辑器连接异常 | [编辑器连接](references/editor-connection.md) |

## 连接与定位

1. 确认任务、本地执行用户和会话位置，按项目映射选择 OpenSSH 别名。核对实际使用的 SSH 程序与配置；配置解析只说明候选连接参数，不证明远端可达。连接参数和密钥选择以该配置为准，不在主文重复维护私钥路径，也不读取或保存私钥内容。
2. 仅在获准连接时验证远端登录身份、主机与 home。区分别名已解析、已登录、目标已核实；认证需要人工交互时说明所需步骤，非交互探测失败不直接判定网络故障。
3. 按项目映射核对远端绝对路径、真实挂载、仓库根、工作树、分支、HEAD、已有改动和相关运行占用。核对解释器、数据、模型与独立输出根；默认登录目录不等于项目目录。权限、容量、GPU 占用属于动态事实，按当前操作需要现场确认。
4. 如需编辑器，按对应参考打开同一目标并再次核对工作区。交付简短映射：别名、远端身份、仓库／工作树、分支与提交、解释器、数据／模型位置、输出根、核验状态与未确认项。普通 SSH 查询不要求打开编辑器。

## 新项目或新服务器

- 新项目在其本地项目知识中登记项目专有路径、环境及资源约定。复用已确认的物理存储，为当前项目选择独立代码与输出位置，不把其他项目的工作树或解释器直接套用。
- 个人主机表属于跨项目共享资料。接入或复核计划若需要写表，应明确目标文件与拟更新字段并获得授权；批准范围已包含该更新时一次完成，不重复确认。仅批准连接或只读核查时，先报告观测和候选更新，不自行写表。
- 获批写表时，按 SSH 别名定位记录，新增主机新增一行，既有主机合并对应字段。保存字段的核验日期、依据和状态，不用一个字段的验证结果代表整行已验证。只读权限观察不等于实际写入成功；必要写入测试限于获批目录并清理自身临时文件。
- 连接失败时保留已确认的本地配置和错误，远端未核实项标待确认；保留历史实测日期，不用失败探测覆盖既有事实。GPU 型号、主机身份和目录分别依据证据。
- 真实条目只写入使用者指定的私有台账。写入前复核最新内容并合并用户增补，公开模板保持虚构示例。读回确认对应别名没有新增重复行、原有信息未丢失。
- 迁移已有项目规则或记录须在获批范围内保留独有信息。新增主机不要求在远端部署对话库或 Skill 副本，进度交接不依赖 GitHub。
- 分支可按项目约定共用环境和数据，但修改公共环境前确认在途任务；输出使用独立 run 目录。连通、路径存在或具备编辑权限，只证明对应基础设施条件，不授权占用 GPU 或启动训练。
