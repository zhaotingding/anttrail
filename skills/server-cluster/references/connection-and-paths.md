# 连接故障分流与工作区核实

仅在对应场景读取。下列动作是获准诊断后的选择，不要求每次全部执行；本地解析与远端登录分别记录结果。

## SSH 配置和密钥的归属

连接信息以实际 SSH 客户端使用的配置为准：命令行选项、用户配置和系统配置可能共同决定结果。常规 Windows 用户配置是 `~/.ssh/config`；使用 `-F`、其他客户端、WSL、容器或其他执行用户时，不能假定共享同一配置与认证代理。

具体主机的密钥路径宜由 SSH 配置的 `IdentityFile` 管理。客户端还可能使用默认身份文件及 `ssh-agent` 提供的身份；`IdentitiesOnly` 可限制所提供的身份。无需在每个项目或 Skill 中复制一份密钥路径清单。[OpenSSH 配置说明](https://man.openbsd.org/ssh_config)

项目记录 SSH 别名和项目路径即可；需要排查认证时核对有效配置、文件存在与访问权限、代理中的公开身份标识，不读取或回显私钥正文、口令。远端通过被授权的公钥验证认证，私钥不因连接操作被复制到服务器。[Windows OpenSSH 密钥说明](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)

## 最小检查动作

| 症状 | 首先核对 | 后续边界 |
| --- | --- | --- |
| 别名无法解析、疑似连错目标 | 实际 SSH 程序、所用配置及该别名的解析结果；核对 HostName、User、Port 和跳板配置 | 不盲试其他账号或主机，不把解析成功当作连接成功 |
| 连接超时、被拒绝 | 从日志区分解析、TCP 建连与 SSH 握手阶段；核对目标及端口和当前网络／跳板条件 | 不直接改防火墙、代理或 sshd，不将超时归因于密钥 |
| Permission denied、身份不匹配 | 有效 User、IdentityFile、IdentitiesOnly、可用认证方式；必要时看 SSH 调试日志和代理身份列表 | 不打印私钥，不擅自更换密钥、删除身份文件或修改服务器认证配置 |
| 非交互检查失败、等待密码／MFA | 是否需要密码、私钥口令或二次认证，当前检查是否禁用了交互 | `BatchMode=yes` 不能替代交互认证，报告需人工处理的环节，不直接认定主机不可达 |
| 主机密钥变化警告 | 是否为预期主机、容器重建或别名重指，依据可信渠道核对主机身份 | 不为消除警告关闭校验或直接删除 known_hosts 记录 |
| 登录成功但目录不对 | 远端主机与用户、home、当前路径、项目绝对路径和真实路径 | 不把默认 cwd 或同名目录认定为目标工作区 |
| 路径存在但不能写／空间不足 | 目录权限、真实挂载、可用空间、配额（适用时）及占用 | 权限位不等于写入实测；不自动迁移、删除数据或修改权限 |
| 终端能连但 VS Code 不能 | 两者是否使用同一 SSH 程序、配置、别名与认证环境 | 转到编辑器参考，不先卸载远端组件或终止会话 |

`ssh -G <别名>` 用于输出生效配置，`ssh -v` 及更高详细级别用于定位连接和认证阶段；只保留与当前问题相关的日志，报告前去掉无关连接信息。[OpenSSH 客户端说明](https://man.openbsd.org/ssh)

## 路径、存储与权限

- 参见 [hosts.md](hosts.md) 的“可直接使用的只读操作”一节，其中列有按需使用的只读命令示例。按当前任务选用，不执行针对其他主机或项目的例子；配置中的自定义命令也须按实际副作用判断，不能把所有本地解析一概视作零副作用。
- 对登记路径核对 `realpath`、挂载来源和文件系统，以及需要时的容量／配额。对代码路径核对 Git 根、工作树、分支、HEAD 和用户改动；对解释器核对当前项目约定和实际位置，不因环境名相同就认为是同一个环境。
- 数据与模型可以按项目约定共用，代码及输出归属必须明确。路径可读不意味着适合放置高频 checkpoint；按当前文件系统、容量和项目布局判断，不强制改成共享盘。
- 仅在获批范围内做必要创建或写入测试，清理自身测试产物。不能因接入或排障顺带占用 GPU、停止进程、迁移环境、删目录或改 SSH 配置。
