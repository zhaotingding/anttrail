# 知识维护与技能迭代

## 范围与授权

- 在获批项目范围内，可主动沉淀、更新或修正项目知识，无需逐次询问；阶段1仍只读。
  项目任务及项目知识维护的授权，不包含全局更新。

- 全局更新按实际影响范围判断，涵盖全局约定、个人通用 Skill（包括本技能自身），
  以及会改变其行为或加载方式的参考文件、脚本和共享入口。
  文件位于项目目录，不代表其跨项目影响可以按项目知识自动处理。

- 发现具有跨项目价值的经验、明确的全局偏好，或现有通用 Skill 的问题时，
  可以主动提出全局更新建议，但不得自行写入或启用。
  更新前须列明目标文件与条款、具体修改内容、依据、影响及验证方式，
  获得用户对该具体方案的明确授权后再执行。
  用户已明确指定更新对象和改法并要求执行时，按获批范围完成，不重复确认。

## 维护与组织

- 先查找已有相关技能、索引与原始证据，确定本次新增或失效的知识。
  不仅在旧摘要之间反复改写；保留用户已有修改，不把一次成功、单机故障或临时选择泛化为通用规则。

- 仅保存明确长期约定、特殊约束、已验证流程、确认故障及解决办法，或修正失效结论；
  注明适用条件与版本、证据位置、验证日期和状态（实际验证／模拟测试／假设待验证）。
  必要的未验证解释标为假设，不写成强制规则。
  不保存聊天流水、普通改动或临时运行状态；这些留在任务或实验记录中。

- 按独立触发的任务或知识域组织，优先更新、合并或修正匹配的已有内容；
  可独立使用且触发不同的内容才新建或拆分，新建前确认没有合适的已有归属。
  不按对话轮次或零散知识点机械拆分，不将全部经验汇入总 Skill。

- 长度控制。
  项目级 SKILL.md 正文不超过 3000 字符，包含标题、列表、链接和代码块，不含 YAML 元数据。
  新增内容前检查长度；预计新增后超限时，先合并重复条款、精简冗余并整理失效内容。
  较长的条件性细节下沉到 references/，正文保留用途和读取入口。
  完成整理后再新增必要内容，并确认正文仍在上限内。
  不为压缩长度删除授权边界、关键约束或改变原意，也不机械拆出多个 Skill 规避上限。
  个人级 Skill 不受该字符上限约束，仍保持主文精简、按需读取参考。

- 项目技能保存于 .agents/skills/<skill-name>/SKILL.md；
  个人通用 Skill 更新已确认的权威目录，不套用项目技能的保存路径。
  各技能写清 name、description、适用边界、必要约束和主要流程。
  条件性细节、长命令、案例和证据放 references/，从正文注明读取时机。
  个人任务 Skill 提供通用方法，项目 Skill 只补充项目特有内容。

- 项目 AGENTS.md 只保留普遍生效的必要约束和简短索引；
  索引写用途或触发条件及路径，不复制正文或要求全部读取。
  维护时同步必要的索引与引用，使后续任务能够按需定位。

- 创建或维护代码项目 AGENTS.md 时，读取[项目初始化与协作参考](../code-development/references/collaboration.md)，
  按其适用范围决定是否补建／补齐；已有文件须读取，但文件存在本身不授权改写。
  适用项目将必要基线实际写入根文件，填写项目事实，已有等价条款复用并保留用户修改。
  按交付范围核对加载与 Git 状态；临时任务、外部局部贡献和只读任务不自动初始化，
  不批量改写其它项目，也不因维护约定自动建库或启用远程保护。

- 冲突处理。
  在当前项目内，项目级 AGENTS.md 和 Skill 优先于个人通用规则。
  处理冲突时核对当前版本、环境、配置、数据和事实依据，不仅凭更新时间判断内容是否有效。
  项目规则不扩大用户授权；修改全局约定或个人通用 Skill，仍须获得明确授权。
  整理冗长、重复或过时内容时回查证据，保留有效结论及来源；
  无法确定时保留限定或待验证状态，不自动推广为全局规则。

- 写入与验证：
  多 Agent 共用时，先明确同一文件的编辑责任；写入前核对最新正文，
  发现他人改动时合并本次差异，不用旧副本覆盖，不无协调并发改写。
  沿用已有协作和版本管理方式，不另建同步框架或强制使用 GitHub。

  按改动检查元数据、引用及必要的选用行为；重要触发或流程调整，
  用典型适用与不适用任务核对实际选择和行为，跨客户端共用时分别验证。
  区分格式检查、原生发现、正文读取和行为验证，不以来源摘要代替执行证据，
  不将单一客户端的结果推广为其他客户端的保证。
