# 程序、环境、配置与个人数据分离

适用于需要安装、升级或持久保存用户状态的应用；采用职责和生命周期分离，不强制拆成多个仓库、磁盘目录或额外框架。已符合要求的布局保留。

- 程序源码、测试、文档和依赖声明由 Git 管理。应用项目的 `installer/` 还跟踪安装、卸载、更新的源码、脚本和配置。构建出的安装／更新程序及随包运行时放在 `installer/dist/`，按发行产物管理；开发环境、构建缓存、凭据和个人数据不提交 Git。
- 配置区分共享默认值、个人覆盖和秘密凭据：默认值可入库；个人路径、账号、偏好不入库；密钥和登录凭据使用项目已有的专门保存机制，导出公开配置时不夹带秘密。
- 数据库、图片、报告、批注、用量记录和用户规则等按项目语义独立保存；源码清理、构建或升级不得顺带覆盖、删除。个人目录位于仓库内部也可以，需有明确读写入口和忽略规则；不要仅为换目录而搬动有效布局。
- 首次应用安装由安装程序部署程序、运行时及依赖，日常从应用入口启动。应用升级交付新版本并保留个人配置及数据。源码开发继续复用项目开发环境，依赖变化时才按声明更新该环境。运行时更新、开发环境迁移和业务数据迁移分别按实际需要处理。
- 确需变更配置或数据库格式时，说明兼容范围并采用必要迁移和恢复办法；不要求用户每次升级重新配置，也不为尚无实际需求的情况搭建通用迁移框架。换电脑、Windows 用户或资料目录时，核对凭据、安装位置、配置和数据恢复条件；源码开发另核对 editable 关联。
- 新克隆应使用共享默认值进入可见的未配置状态，不能依赖维护者的个人文件、密钥或数据。需要用户填写的连接信息在对应功能启用时明确提示；配置恢复后须保留原有自动任务、计费和外部操作的授权边界。
