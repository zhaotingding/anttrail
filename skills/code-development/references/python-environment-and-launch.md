# Python 开发环境与安装后运行

适用于 Python 源码开发、测试、构建和应用安装交付。源码工作使用项目开发环境，安装后的应用由安装程序交付运行时和依赖。

## 源码开发、测试与构建

- 每个 Python 项目使用独立 Conda 环境，安装项目声明的 Python 与依赖。项目依赖不安装到公共 base、全局 Python 或用户 site-packages，Conda 内不再嵌套 venv。
- 在 PowerShell 中通过 `conda run -n <项目环境> ...` 执行源码、测试和构建，实时日志按需使用 `--no-capture-output`。依赖可使用该环境的 `python -m pip` 安装，沿用唯一依赖声明。
- 从 `conda info --envs` 与项目约定选择或创建独立环境。用 `sys.executable` 和 `python -m pip --version` 核对环境归属。公开示例使用环境名，环境根目录由使用者决定。
- 开发环境迁移按获批范围进行。先核对活动进程，再检查新前缀、依赖、editable 关联和 Windows 命令启动器。开发环境和包缓存不进入 Git。

## 应用安装与日常启动

- 应用使用安装程序交付，安装时部署程序、所需 Python 运行时及业务依赖。已安装的主程序和本地 Python 后端都从安装内容启动，不要求用户准备 Conda、激活环境或保留源码仓库。
- 依据项目现有构建链封装所需依赖。可采用 PyInstaller 或合适的运行时打包方案，确认实际使用的动态导入、资源和原生库已随包交付。构建针对目标平台和架构完成。
- Python 后端由应用定位到随包解释器或已封装的可执行程序。使用安装后的真实路径与进程验证，避免启动到 PATH 中的开发解释器或维护者目录。
- 应用交付不再采用“轻量 EXE 调用用户 Conda 环境启动源码”的默认方式。已有入口的迁移在相应项目获批范围内完成，保留用户配置与数据。
- 安装、卸载和更新的目录与 Git 规则统一按[桌面 UI 与应用交付](desktop-ui-and-app-shell.md)执行。影响已交付程序的代码或依赖变化，通过重新构建的安装／更新产物交付。

## 说明与验收

- README 先说明安装包的位置、安装步骤、应用入口、更新与卸载方式、个人资料位置。源码开发的 Conda 准备和命令放在独立的开发说明中。
- 安装验收从真实安装包开始，在缺少项目源码和 Conda 开发环境的测试环境运行应用。核对主程序、Python 后端和依赖的实际来源，完成一条真实业务流程。窗口打开和后台功能完成分别留证。
- 用户保留的手动步骤按[手动安装验收](manual-install-validation.md)处理。真实安装、构建检查和源码测试分别报告。
- 原理依据为[PyInstaller 的运行时封装说明](https://pyinstaller.org/en/stable/operating-mode.html)，于 2026-11-15 核对。它说明封装机制，具体项目仍须验证动态依赖和实际运行。
