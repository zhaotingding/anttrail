# 用户手动安装验收与升级保留

适用于用户亲自验证应用安装、升级、卸载或已有配置恢复，以及明确提出的源码开发环境验收。依据用户确认的资料保留要求，2026-11-15 改为安装包交付，2026-11-16 补充 Windows 目录选择、迁移和基础设置要求。实际验收结果按项目记录。

## 交付与验收边界

- 用户明确要求自己创建环境、安装、配置或启动时，Agent 先完成获批的最小调整和必要静态／隔离检查，再交付逐步操作说明；不代替用户执行其保留的验收步骤，不为制造干净状态删除现有环境、个人资料或停止生产应用。

- 首次干净安装与已有用户升级分开验证：前者从安装包及初始配置确认应用和后端可运行，后者验证新版本及设置、数据保留。只有用户反馈了实际结果，才能标记相应手动验收通过；Agent 测试通过与用户验收通过分别报告。

## 先确认现状

检查当前仓库、用户改动、README 和入口实现，列出四类内容的实际位置与管理者：

| 类别 | 要确认的内容 |
|---|---|
| 程序 | 源码、应用入口、唯一依赖声明、installer/ 内的交付实现及实际产物 |
| 环境 | 安装目录内的运行时与依赖来源、目标平台及写权限；源码验收另核对项目开发环境 |
| 配置 | 共享默认值、本机覆盖、凭据来源；谁读取、谁写入、何时生效 |
| 数据 | 数据库、文件、规则、历史记录与会话；哪些是用户资产、哪些可重建 |

按实际影响确定必要调整。目录已经分离且生命周期正确时保留，避免重写业务、统一所有项目的文件名，
或新增无人需要的配置管理层。README、当前实现和用户修改不一致时先核对，不能恢复用户明确删除的旧稿。

## 安装、迁移、升级与卸载验收

目录或安装流程改动，至少用实际安装包完成新装、原位覆盖和改路径迁移；行为要求及失败边界见[Windows 安装、迁移与首次设置](desktop-ui-and-app-shell.md#windows-安装迁移与首次设置)。

- 首次安装：从项目 `installer/dist/` 或指定发行位置取得真实安装包 → 在没有项目源码和 Conda 开发环境的测试环境操作默认路径及“浏览”选择 → 安装后从完成页打开基础设置 → 核对随包运行时、主题和适用的 API 密钥填写／跳过 → 完成真实业务流程。
- 原位覆盖：安装器预填已登记目录并允许保留原路径更新 → 完成页打开基础设置并回显旧值 → 核对密钥留空未覆盖、已有设置及历史数据保留，不出现要求重新决定是否保留资料的步骤。
- 改路径迁移：通过“浏览”选择新位置 → 核对旧安装、目标目录与资料边界后确认迁移 → 旧程序移除成功后完成新位置安装 → 核对有效程序与安装记录唯一、快捷方式和实际启动路径正确、原资料可读。旧程序移除失败时须停止；使用隔离安装实例验证，不清理生产应用。
- 版本升级：安装真实旧版本并保存测试配置和数据（包含用户自选资料目录）→ 核对自动检查及新版提示 → 点一次“更新并重启” → 核对下载验证、正常关停、新版自动进入原工作台以及原设置和数据读回。详细成功、失败与正式发布验收按[桌面交付参考第 6 节](desktop-ui-and-app-shell.md#6-验证按本次变化选择)执行；手动覆盖新版安装包只能证明覆盖升级，不能代替应用内一键更新验收。
- 程序卸载：通过项目卸载入口或系统“已安装的应用”卸载 → 核对程序和安装登记已移除、个人资料按约定保留。只有用户明确选择清理资料时，才验证对应清理范围。
- 源码开发验收：仅在用户明确要验证源码时，按[Python 开发环境](python-environment-and-launch.md)准备项目 Conda 环境、安装依赖并运行源码测试。这些步骤不作为已安装应用的启动前提。
- 用户只需升级时复用现有配置和数据。干净安装测试使用隔离的测试环境，保护在用应用及用户资产。

## 交给用户的说明

尽量复用 README，只补齐本次必要步骤，避免再造一份很快过时的完整教程：

- 每组命令注明执行目录、窗口权限、首次或重复操作、预期结果及失败后需要反馈的错误。
- 提供可双击安装包的实际位置，标明未签名本地验收或正式发行用途；写清用户需选择的实际安装路径、正常启动入口、卸载和更新方式及所需权限，并列出已验证与仍待验证步骤。
- 按“安装程序 → 选择目录 → 完成页打开基础设置 → 调整或跳过 → 验证结果”提供手动步骤；自动更新沿用原位置和设置进入工作台，不重复首次设置。
- 核对安装后进程路径、随包解释器及依赖来源。用户另行验收源码时，再提供 Conda 环境检查方法。
- 标明个人配置、数据和密钥分别如何保留；同电脑同用户和换电脑／换用户的恢复条件不同。
- 恢复数据库前先停用相关写入者或使用一致性备份方法；不要把运行中的单个数据库文件复制当作可靠备份。
- 恢复旧设置可能恢复自动任务。先告知哪些设置会触发网络、计费或外部操作，不能默认新配置的安全初始状态仍适用。
- 写清“窗口打开”“后台就绪”“连接成功”“业务数据到达”的区别；哪一步没有结果，就只记录到前一步。

## Agent 与用户的验证边界

Agent 可以完成已获授权的代码修正、文档检查和必要隔离测试；用户保留的实际环境创建、安装、启动、
登录及业务操作由用户执行。已有测试环境可以按授权用于离线检查，但不能替代用户的新安装体验。
不要为了此类验收自动安装 Conda、迁移生产数据、批量删环境、重启在用程序或调用付费服务。

交付时分别列出 Agent 已验证、用户待验证和明确未覆盖项。用户反馈具体错误后，先定位所属层：
安装程序、路径、目录写权限、文件占用、随包运行时、依赖、配置还是业务连接，再修实际缺口。
不得将静态检查、模拟登录或历史结果写成当前用户安装成功。
