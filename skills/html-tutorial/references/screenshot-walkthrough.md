# 真实截图、编号标记与逐项讲解

适用：软件界面、工具操作、日志／结果面板或用户截图的 HTML 讲解。用户提供了相关截图，或当前任务允许使用 computer-use 获取截图时，优先把真实界面作为教学底图，帮助读者把说明直接对应到位置。

## 来源与取图

- 优先复用用户提供且能表达当前问题的截图。确需新截图时，先遵循当前可用电脑操作工具及其使用规则，在已授权的应用和范围内采集；不能为了凑截图执行提交、删除、付款、部署等未授权动作。
- 保存截图来源、对应页面／视图、可确认的软件版本、截图时间和截取状态，并在图片标题或图注中显示必要信息。未知版本标“未核实”，未知截图时间标“未提供”；不将教程生成日期或文件修改时间冒充截图时间。
- 截图中的数量、选中对象、分支或任务状态只说明截取当时。需要时提示界面可能随版本或布局变化；没有证据时不补造版本、图标名称或实时状态。
- 尽量保留足以定位的上下文。原图模糊或目标被遮挡时，说明缺口，必要时请求更清晰材料；可在获准范围核对 tooltip 或相关文档，不猜测按钮功能。
- 需要脱敏、裁剪或放大时处理派生副本并说明，不改变教学相关的界面事实。不得用生成式重绘替代真实界面而不标明；示意界面必须明确标为示意。
- 将获准使用的截图随教程保存为本地资源，或在明确需要单文件时内嵌。不要长期依赖剪贴板临时路径、用户机器的绝对路径或在线图片；截图本身属于教程材料，不固化进通用 Skill。

## 编号和讲解设计

先选择对当前学习目标有意义的区域，再按阅读或操作顺序编号。无需固定六个点，也不要求把每个按钮都编号；密集区域分组、分图或局部放大，避免标记互相遮挡。

每个编号至少能够回答：

| 项目 | 讲解内容 |
| --- | --- |
| 位置与对象 | 在哪个视图、哪个区域，当前针对什么对象 |
| 作用与使用 | 这部分解决什么问题，何时使用，必要时怎样操作 |
| 反馈与解读 | 操作后应观察什么，截图里的反馈实际说明什么 |
| 上下文与边界 | 容易混淆的对象、模式、权限或版本差异，截图不能证明什么 |

这些是内容检查点，不要求每个简单标记都生成四块大卡片。关键说明紧邻截图；桌面可并排展示，窄屏可放在图下，保持当前编号和上下文可见。

图上编号、编号列表和讲解面板使用同一份标注数据及稳定 ID。可记录图 ID、点 ID、定位坐标或区域、标题及说明；多图切换不能混用另一张图的编号与内容。编号数字在不同图里复用时，组合图 ID 区分。

## 同一视图的真实前后对照

- 讲解操作引起的状态变化时，优先考虑操作前／后的同一视图并置、切换或差异高亮，突出哪些区域发生变化、哪些保持不变，以及反馈能证明什么。仅在确有教学用途时采用，不要求每个标记都增加一组对照。
- 对照图必须实际取得并标明前后状态。尽量保持观察对象、视图、缩放和裁剪范围可比；不可避免的布局或版本差异应说明，不将其都归因于该操作。布局不同的图不强行变形叠合。
- 缺少操作后截图时说明缺口，不重绘结果冒充实拍，也不为取图执行未授权操作。对照切换时同步图片、当前状态、编号与讲解，保留完整截图的查看入口。

## 图片和标记如何保持对齐

- 保持原图宽高比，优先用独立 HTML／SVG 标注层叠加，不把编号永久涂进原图。以实际显示的图像内容区域为坐标基准，不以整个页面或含留白的外框定位。
- 明确记录标注坐标的基准尺寸和单位，原图像素坐标与归一化坐标不能混用。计算相对位置时，坐标与尺寸必须来自同一基准，再映射到实际显示的图像内容区域；不能未经核对就把原始截图像素坐标除以密度修正后的 naturalWidth／naturalHeight。
- 图片和标记采用一致的显示变换；裁剪、object-fit 留白、缩放和平移产生的偏移都应同步处理。在同一 CSS 坐标系中的 HTML／SVG 标记不重复乘 devicePixelRatio；Canvas 的绘图分辨率和显示坐标单独处理，不把“禁止使用 DPR”当通则。
- 标记靠近目标且避免挡住关键文字。需要时用引线或局部高亮；原图过密时提供原图／局部放大，而非把整张图压成看不清的小图。
- 点击图上编号或编号列表时，选中样式和讲解同步。是否提供上一点／下一点由实际导览需要决定，不额外堆无用途控件。
- 标记使用可操作的控件，具备“图号＋编号＋对象”的可理解名称、键盘焦点和选中状态。不能只靠 hover 或颜色提供解释，触屏也能选择并阅读。

`devicePixelRatio` 表示物理像素与 CSS 像素的比例，`naturalWidth` 是密度修正后的固有 CSS 宽度；坐标体系一致的标注不因高分屏本身必然漂移。[DPR 说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)、[naturalWidth 说明](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/naturalWidth)

## 图片清晰度与体积

- 以关键文字、数字、图标和标注目标可辨认为前提，先裁掉无关区域或提供局部放大，再选择合适的格式、分辨率和压缩程度。可按实际截图比较 PNG、无损 WebP 或其他合适编码，不统一规定所有图片必须使用某种格式。
- 压缩或降采样后检查关键细节；不为满足单图约 300 KB 等固定上限而压糊文字。需要时使用阅读预览与按需查看原图，保留来源及处理说明，图片派生尺寸变化后重新核对坐标基准。
- 检查整页及随附资源的体积、加载和操作响应；多图按需加载，不为体积小而隐去必要上下文，也不默认把所有大图同时解码或展示。交付时说明有实际影响的大资源和使用限制。

## 空、加载与失败状态

- 图片未就绪时显示加载状态，不先把热点放到错误的位置；加载后依据真实图片尺寸定位。
- 图片缺失或无法解码时给出明确反馈，仍可阅读编号说明；不要展示貌似正常的空图或错图。未核实目标不强行标成确定入口。
- 只保留与当前导览有关的视图和更新。隐藏图片不需要持续运行无意义动画；大图、多图的加载与缩放要按实际页面响应检查，不以固定 SVG 数量代替性能判断。

## 验证

1. 对照真实图像，逐项核对“图—编号—对象—说明”，检查重复、遗漏、遮挡和未经证实的功能解释；来源、已知版本与截图时间在页面中可见，未知信息没有被补造。
2. 实测图上标记与编号列表的选择联动、切图、前后对照、放大、重置及实际支持的键盘路径；图与讲解始终属于同一状态。对照中的差异有真实图像依据。
3. 在目标布局、窄屏及允许的缩放／裁剪状态下检查位置；适用时覆盖浏览器缩放与跨显示器场景，确认没有坐标混用、漂移或留白误定位。压缩后关键文字、数字和图标仍清晰。
4. 按承诺验证离线图片加载及错误反馈。原图查看与静态编号说明仍可定位；教学页面中的交互不等于已在真实软件中执行对应操作。
5. 检视包含内嵌图片的 HTML 时，先定位 DOM／脚本或屏蔽 data URI 编码，只读取必要片段，不把整段 base64 当作审查材料输出。

验收侧重读者能否找到对象、理解操作和反馈。源代码中存在热点或按钮不能代替浏览器验证，也不能证明用户已掌握；工具限制与未完成检查须如实说明。
