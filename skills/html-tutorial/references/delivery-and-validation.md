# 可读性、离线交付与验证

适用：开始实现、决定资源组织、交付前验证及局部修复。采用项目已有工具，不为一次页面开发自动建立框架或重型测试系统。

## 可读性与可访问性

- 用户和项目风格优先；否则使用柔和深色默认。浅色切换、打印和导出按需求提供，不为每个小页面强制增加主题系统。需要打印时检查图表、背景和展开内容的打印效果。
- 正文可从约 16–18 CSS px、1.5 左右或更宽松行高开始，根据字体、设备和内容实测调整。英文长文约 60–80 字符、中文约 30–40 字每行可作初始参考，不机械套到公式、代码和数据表，也不规定每段最多四行。
- 正常正文对比度以至少 4.5:1、大字至少 3:1 为核对基线；不能只看色相差异。大字与例外按标准定义判断，不把所有元素都当大字降低要求。[WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 使用语义标题、表格表头、清楚的控件标签和可见焦点；关键功能可键盘操作。图形有必要的文字解释，含义不只靠颜色表达，触屏也能获取关键说明。
- 窄屏和放大后保持合理阅读顺序；必要的宽表和代码区域可局部滚动，不能让整页文本横向溢出。减少动态时，核心内容仍可阅读。

## 资源组织与离线

- 区分单文件 HTML、本地资源包和明确允许联网的页面。只在明确要求或确有便携收益时内嵌全部资源；资源包同样可以离线，不按正文字数或控件数量自动拆分。
- 核心学习路径、必要媒体、字体、脚本和样式应在交付资源中。在线扩展明确标注，离线时不让关键解释、公式或操作失效；若必要材料无法取得，说明缺口，不能把链接当本地资源。
- 直接双击的页面采用与 file:// 相容的资源组织。需要读取数据时选择实际可用的内嵌数据、本地随附资源或用户文件选择等方式，并验证；不凭 HTTP 成功推定本地 fetch 或模块加载也成功。
- 数据内容嵌入页面时按上下文正确转义；示例和用户导入内容不应被当作可执行脚本。不要为简单静态教学引入无必要后端或在线账户。
- 构建／验证工具与交付依赖分别说明。使用已有浏览器自动化工具不意味着读者要安装它；KaTeX 等本地库也不等同于在线依赖。确需安装、下载或增加工具时遵循当前授权。[Playwright 的工具用途](https://playwright.dev/docs/library)

## 验证顺序与实际证据

1. **内容与数值**：核对必要定义、符号、输入输出、数据处理和结论范围；自行构造的例子明确标识。
2. **学习路径**：用与目标相符的问题检查能否定位解释和依据；重要概念是否有缺失前提或跳步；形式是否表达了预期关系。少量学习检查用于暴露误解，不能以浏览完成率、模型自评或规则复述证明学会；读者未参与测试时，不宣称已测得学习时间或学习效果改善。
3. **真实渲染与操作**：实际浏览器查看主路径和本次相关控件，核对文本、图表、公式、焦点、遮挡、状态切换，以及数值和文字同步、重置／回退。截图只证明某一时刻的显示，不代替交互测试；涉及截图导览时还需按[对应参考](screenshot-walkthrough.md#验证)检查标注、对照和缩放。
4. **交付环境**：承诺离线双击则在实际 file:// 下验证，并在离线条件检查资源完整；窄屏、打印、媒体、导出、阅读状态保存按承诺验证。不同协议或浏览器验证不能互相冒充。
5. **交付记录**：给出入口、资源和使用方式，列实际检查、已知限制和未验证部分。局部改动只测试相关行为和直接影响，不反复审计全页。

区分源码或逻辑检查、HTTP 预览、file:// 实测和读者学习证据，不将其混为同一种验证。工具无法访问某种协议、不能操作浏览器或缺少环境时，保留产物并准确报告，不绕过限制或用模拟结果冒充实测。必要检查通过后及时交付。

学习自测可以检验预测、解释、比较或迁移，数量按知识点和用户负担安排。选择题与展开答案只是形式；不以固定五题、选项随机或模型复述正文证明教学有效。
