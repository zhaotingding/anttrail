# 按知识关系选择视觉与交互

适用：决定图形、页面形态和操作方式。选择的依据是读者要理解的关系，不是最新组件或固定模板。

| 目标／关系 | 优先考虑的表示 | 需要时加入的交互 | 应避免 |
| --- | --- | --- | --- |
| 概念层级、分类与组成 | 层级图、分类树、分层结构图 | 展开子层并保留父层位置 | 无关系的卡片堆积；把分类画成因果 |
| 易混概念或方案差异 | 同尺度并置、对比表、差异高亮 | 同步选条件、显隐差异 | 分散到很远的章节，要求读者记住再比较 |
| 流程与执行顺序 | 流程图、步骤轨迹、时间线 | 当前步骤高亮、前进回退 | 静态图已清楚仍强制动画；把顺序误画成因果 |
| 状态与分支 | 状态机、决策树、条件—结果表 | 改条件并显示走过的路径 | 只展示最终状态，隐去触发条件 |
| 因果或机制解释 | 带条件与证据标记的机制图、控制变量对照 | 改变一个有解释价值的输入 | 仅凭箭头、时间先后或相关性声称因果 |
| 数量、分布与变化 | 按问题选折线、散点、区间、直方或表格 | 筛选、并置、查看原始点与处理方式 | 截轴不说明、无单位、只展示最好结果 |
| 数学与算法内部 | 公式—数值—图形联动、矩阵或张量视图、代码走查 | 单步执行、参数变化、状态回看 | 只贴整段代码；图和公式各说一套 |
| 论文与证据关系 | 问题—方法—证据—局限结构、近邻对照 | 展开证据和来源、比较假设 | 把论文标题列表当研究综合 |
| 软件界面、操作入口与截图反馈 | 真实截图＋编号标记＋逐项讲解 | 图上标记与编号列表双向联动、局部放大 | 重绘假界面、猜测模糊图标、编号遮挡目标或与说明错配 |

涉及真实截图时，按[截图标注导览](screenshot-walkthrough.md)处理来源、定位、联动及验证；这是一种优先采用的教学机制，不限定某个产品、配色或左右分栏比例。

## 先选页面形态

- 长页适合连续解释与回查，提供目录和清楚层级，不把长等同堆字。
- 分步场景适合过程，保留概览和直接跳步；不是所有章节都做幻灯片。
- 数据探索页适合条件比较与结果定位，给出默认阅读路径，避免没有解释的仪表盘。
- 速查页适合稳定定义、关系和操作入口，不要求整套教学闭环。

一种页面可组合形态，但保持导航和视觉语义一致；页面是否拆分由独立学习单元、资源大小和维护方式决定，不由三个控件或三千字决定。

## 交互的最低解释要求

每个控件须能说明它对应的问题、允许的输入、保持不变的条件和观察结果。参数旁显示数值与单位，必要时注明合法范围；越界、缺失或未支持状态不能静默变成貌似正确的演示。

对照视图应保持可比坐标、尺度或明确说明差异；突出当前变化，保留前后参照。改变输入后同步图形、计算值、文字说明与示例状态。重置恢复清楚的初始状态，不只重画图。

动画只用于说明变化过程。提供需要的暂停、步进和速度控制，允许静态查看；避免自动轮播、装饰性视差或持续闪动抢走注意。非必要运动应尊重减少动态偏好。[W3C 动画交互说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

优先以清楚命名、布局、单位、图例和少量就近说明降低理解成本；不是每个动作都弹出长提示，也不能把关键解释仅藏在 hover 中。
